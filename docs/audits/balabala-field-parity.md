## 本次修复与验证边界

- 发布阻断：plan/publish 在读取凭据和远端请求前校验阻断项，合并后再次校验。缺必填/销售属性、价格或真实尺码事实不能仅靠改变工作流状态放行。sync 和普通 override 保留未解决阻断。
- 价格：默认从本地 SKU Excel 的挂牌单价归并；所有 SKU 都必须有有效正数且同款一致。缺失/冲突不回退上市计划价。拼多多单买/团购按 -1/-2，结果不能成为零或负数。历史显式 SPU 价格对象输入保留兼容，但无新增 MDM 接口或额外 JSON 要求。
- 鞋表：主表厘米，唯品会原始毫米；26 码运动鞋内长的 `170.32mm` 保留到最终 SDK。欧洲码裸数字，展示行键带“码”。修复 payload 对英文 `shoe/apparel` 类型的识别。
- 充绒：逐尺码实证参与销售尺码备注、唯品会、抖音和多平台联动；主表已有克重列时填充，保持固定表头。缺码、冲突、AI 事实、百分比、未分配范围不能代替逐码克重。原 OCR 事实留在 normalized 审计中，重复组装保持一致；普通增量/标量 override 不允许孤立修改充绒字段。
- 图包：混合目录按正式来源款号隔离，保留文件路径、SHA256、角色；不做 OCR 推测或上传。

回归包含模拟 fetch/Java 的六个 plan/publish 阶段阻断、价格缺失/冲突、鞋半码/凉鞋缺结构、最终 SDK 单位与行键、充绒传播和 OCR 重复组装。初次审核另有 15 个服饰类目 × 5 张表的 75 个合成对照通过；这些都不等于真实当前模板和深绘持久化验收。

## 2026-09-08 正式本地资料复测补充

本次只对 `204426140121-test` 写入；`107128/107033/108104` 按用户要求排除，`107129/108035/121024` 因本地字段与量点仍存在真实阻断未发布。当前模板逐字段实测结果另见 `balabala-current-field-validation.csv`；历史 5,982 行不因此自动转为已验证。

- MDM 来源是本地商品 SKU 工作簿。SPU 取数使用正式 sourceSpu；远端地址使用精确 targetSpu。不得用测试后缀筛选正式资料。
- 价格区间当前接口实测写入 `1,359.9`，回读为 `1:359.9`，不能直接沿用 Listingify 的 `1:359.9` 输入，也不能把远端 Map.toString 文本写回。解析只接受有效数字对，异常嵌套文本保持 mismatch。
- `dp.product.incremental.update` 携带含 `*` 备注的鞋码会错误重映射尺码和 SKU。本次测试发现后已全量恢复并确认 15 个整数鞋码、30 SKU 和所有尺码表。状态型入口与 Java adapter 均新增前置拒绝；这类商品须使用审阅后的 full-update。
- `25鞋子尺码表` 是 SINGLE_CHOICE 模板选择器，不能仅凭名称含“尺码表”把它变成结构化表。
- 回读按实际发送 SDK 商品体校验，并解析顶层 sizeTables、skus.skuItems；SKU 除颜色/尺码键外还逐列检查价格、条码、货号等值。多选顺序不影响值比较；真实量点、毫米小数不做近似放宽。
- 未返回的平台必填字段保持 mismatch；销售尺码备注和多文本顺序无法通过资源接口直接确认时保留 UI 复核，不以 10200 代替验收。
